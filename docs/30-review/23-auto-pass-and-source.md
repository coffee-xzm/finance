## 1. `source ./devenv.sh` 只在**编译**时需要

本机 `~/.cache/go-build` 与 `~/go/pkg` 是**只读挂载**，Go 默认写入会 `read-only file system`。
`devenv.sh` 把 `GOCACHE`/`GOMODCACHE` 改到仓库内。

| 场景 | 是否要 source |
|---|---|
| `go build` / `go run` / `go test` | ✅ **要** |
| **直接跑已编译的二进制** `./bin/serve` | ❌ **不要** |

**推荐做法**：编译一次，之后直接跑二进制。

```bash
cd finance-router
source ./devenv.sh                  # 只这一次
go build -o bin/serve ./cmd/serve   # 编译
./bin/serve                         # 以后直接跑
```

`bin/serve` 已编译好（约 17 MB 单文件）。

## 2. 自动通过策略：**没察觉到错误就不打扰人**

### 2.1 原来的行为（已改）

每一行都写 `人工审核 = 待审` —— 即"**每行都要人确认**"。

当时的理由是"机器会错"（¥4.60 那张票的 10 倍错误就是例子）。
但你要的是更实用的取舍：**机器没发现问题就不该占用人**。

### 2.2 现在的行为

配置项（`config.yml`）：

```yaml
review:
  # true  → 只有出错的行才需人工：不通过才发私信
  # false → 每行都要人确认（更保守，但费人力）
  auto_pass_clean: true
```

| 核对结果 | 人工审核 | 是否发私信 | 是否归档 |
|---|---|---|---|
| **一致** | **自动「通过」** | ❌ 不打扰 | ✅ 服务自动归档 |
| **存疑 / 缺件** | 「待审」 | ✅ **发私信给你** | 等你处理 |

**服务里的顺序**：`extract → sync → archive（自动通过的那些）→ notify（只通知待审的）`

### 2.3 一条重要的保护

**绝不覆盖人已做出的判断**。更新已有行时：

- `人工审核` 已是「通过」或「驳回」→ **保持原样**
- `人工审核` 还是「待审」且核对一致 → 允许自动改为「通过」

> 这就是"自动通过"与"人工决策"的边界：**机器只处理人还没表态的行**。

### 2.4 策略变更后补正历史数据

策略是后加的，之前的行可能还是「待审」。新增一个**不需要重新识别**的补正模式：

```bash
go run ./cmd/sync -recheck
```

它只扫描源表，把「待审 且 核对一致」的改成「通过」，**不动人已表态的行**。

实测：

```
扫描源表 7 行，策略：核对一致 → 自动通过
  ✓ 7729EEDC 已自动通过
  ✓ <INSTANCE_A> 已自动通过
  ✓ <INSTANCE_B> 已自动通过
  ✓ 4C37F5AF 已自动通过
  ✓ AA774403 已自动通过
完成：补正 5 行
```

## 3. 顺带修掉的一个真 bug：归档"没有图"

补正后归档时提示：

```
完成：归档 6，跳过(已存在) 0，失败 0
注意：5 条没有带上图片（本地文件已清理或未跑过 extract）—— 图仍可在源表查看。
```

### 3.1 根因

**附件不能跨表复用 `file_token`**（官方限制），所以归档到「报销整合」时必须**从本地重新上传**。
而 `archive` 原来是去 `data/extract/manifest.jsonl` 找本地路径 ——

> **但 manifest 每次运行会被整体重写**（`os.Create`），只剩最后一批实例。
> 于是早先处理的行归档时"找不到图"。

### 3.2 修法（迁移 0003）

把预处理图的本地路径**落到库里**：

```sql
ALTER TABLE evidence ADD COLUMN local_png TEXT NOT NULL DEFAULT '';
```

`archive` 改为按实例号从库里查路径：

```go
imgs, _ := db.LocalImages(ctx, inst)   // slot → 本地图
```

实测新抽取的实例已正确落库：

```
AA774403-… 发票文件 → files/AA774403-…/invoice-1-1.png
AA774403-… 订单截图 → files/AA774403-…/order-1.jpg
AA774403-… 付款截图 → files/AA774403-…/payment-1.jpg
```

### 3.3 ★ 两级兜底 + 补历史（用户追问"为什么整合时没把图转过去"后补做）

用户追问后复查：**源表 8 行都有 3 个附件，整合表只有 2 行有**。

原因确认是两个叠加：
1. `archive` 从被覆盖的 `manifest.jsonl` 找路径 → 找不到；
2. `evidence.local_png` 是**事后**加的列 → 历史行为空。

**修法：加第二级兜底 —— 扫目录**

```
取本地图的两级来源：
  ① evidence.local_png            （新数据都有）
  ② 扫 data/extract/files/<实例号>/  （历史数据兜底）
      按文件名前缀还原槽位：invoice-* → 发票文件，order-* → 订单截图，payment-* → 付款截图
```

**并加补历史模式**：

```bash
go run ./cmd/archive -repair -dry-run   # 先看要补哪些
go run ./cmd/archive -repair            # 真补
```

实测：

```
扫描整合表 8 行，找缺附件的
  ✓ 4C37F5AF 已补 3 张图
  ✓ 7729EEDC 已补 3 张图
  ✓ <INSTANCE_A> 已补 3 张图
  ✓ <INSTANCE_B> 已补 3 张图
  ✓ <INSTANCE_C> 已补 3 张图
完成：补图 5 行，跳过（已有图）3 行
```

**结果**：两张表 8 行 × 3 张附件，全部齐了。

#### 3.3.1 同一类 bug 的第三次出现

修这个时**又踩了同一个坑**：`scanLocalImages` 返回的路径已含 `data/extract`，
而 `readLocalFile` 会再拼一次 → 读文件失败（第一次只补上 1 行）。

> **教训**：这个项目里"相对路径的基准"必须**只有一个约定**。
> 现在统一为 **相对 `data/extract`**，并在注释里写明。

#### 3.3.2 一处历史不一致（未处理）

整合表里有 3 条的发票附件是 `application/pdf`（早期归档留下的），
另 5 条是 `image/png`。**新数据统一是 PNG**（可内联预览）。

要统一的话，删掉那 3 行重跑归档即可 —— 但那是测试数据，没动。

## 4. 现在的完整流程

```
飞书审批被提交（长连接推事件）
   ▼
serve：幂等 → 状态机 → 入队
   ▼
extract：下载三图 → PDF转PNG → 识别 → 本地入库（含 local_png）
   ▼
sync：落到「报销核对」
   ├ 核对一致 → 人工审核=通过
   └ 存疑/缺件 → 人工审核=待审
   ▼
archive：自动通过的行 → 复制到「报销整合」（含图）
   ▼
notify：只给「待审」的行发私信给你
```

**你的日常**：只在收到私信时才需要打开表格看——没消息就是一切正常。
