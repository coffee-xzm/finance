## 0. 先明确"这一步在为谁验证"

插件（`bitable-plugin/`）里**没有一行逻辑能在本机证明它在飞书沙箱里跑得起来**：
SDK 只有在多维表格的侧边栏宿主里才有 `window.bitable` 之类的注入。
所以 T1 是**唯一**能把「代码写完了」变成「财务真的能点到 zip」的一步。

| 编号 | 验什么 | 通过标准 |
|---|---|---|
| T1 | 插件能在真实多维表格里加载并产出 zip | 侧边栏出现界面；勾 2 条记录 → 下载 → zip 解压后文件名/目录/`manifest.csv` 都对 |
| T2 | 沙箱里走哪条网络通道 | 右上角徽标显示 `本地打包 · tt.request`（或 `fetch`），**不能是空白/报错** |
| T3 | 大批量（数十条 × 3 附件）不炸 | 10 分钟链接不失效、并发不超 5、进度能从 `下载中 n/m` 走到完成 |
| T4 | 与官方「附件批量下载」插件对拍 | 同一批记录两条路各导一次：**文件数一致**，文件名可按规则互相对上 |

## 2. 步骤 A · 把插件托管到 Replit（拿到 HTTPS 地址）

两条路，任选一条。**推荐 A-1**（不用装依赖、不用打包上传）。

### A-1 Fork 官方模板 + 覆盖本工程源码（推荐）

1. 打开官方 React 模板 <https://github.com/Lark-Base-Team/react-template>，
   在 Replit 里 **Fork** 成自己的 Repl（官方环境准备文档就是这么写的）。
2. 在 Replit 的文件树里，把**本工程这些文件**覆盖进去：

   | 覆盖对象 | 说明 |
   |---|---|
   | `src/` | 整个目录替换（含 `api/`、`core/`） |
   | `index.html`、`package.json`、`vite.config.ts`、`tsconfig.json`、`tsconfig.core.json` | 直接替换 |
   | `.replit` | 用本工程的（`run = "npm run dev"`） |
   | `testdata/`、`scripts/` | 可选，只影响本机测试 |

   模板原有的 `src/App.jsx` / `src/index.jsx` / `public/` 不再被引用即可。
3. 点 **Run**（或 Shell 里 `npm install && npm run dev`）。
4. 起来后，**点 Webview 右上角的「New Tab」，复制那个 URL**
   （形如 `https://<uuid>.xxxx.replit.dev`）。**这个地址就是要填进多维表格的「服务地址」。**

### A-2 直接上传本工程的 bundle

```bash
bash bitable-plugin/scripts/bundle-for-replit.sh    # 生成只含源码的 zip（约 60KB，已排除 node_modules/dist）
```

把生成的 zip 传到 Replit（Create Repl → Import from zip，或先推 GitHub 再 Import from GitHub），再点 Run。
路径在 `.scratch/dist/bitable-plugin-<时间戳>.zip`。

### ⚠️ Dev URL 不是长期地址（官方原文）

| 事实 | 后果 |
|---|---|
| Dev URL **只在你正在编辑该项目时存活，每次重开地址可能变** | 地址一变，多维表格里那个插件就得重填 |
| 官方明说它**只适合测试** | 给小范围试用可以，别当正式入口 |
| 免费 Starter：**1 个**已发布应用，**30 天后自动下线**（可重发） | 要长期稳定就重新发布 |
| **Static 部署**：托管**免费**，只按流量计费（$0.05/GB），无后端 | 本插件是纯静态前端，**最匹配** |
| Autoscale 部署：空闲 15 分钟缩到 0 | 会有冷启动延迟，不推荐图省事 |

长期方案：Replit **Static** 部署 —— 公共目录填 `dist`，build 命令填 `npm run build`。
本工程已满足官方三条硬要求（`vite.config.ts` 里 `base: './'`、无 history 路由、`package.json` 里有 `"output": "dist"`）。

## 3. 步骤 B · 把地址填进多维表格

帮助中心原文：「打开任意多维表格，点击右上角 **多维表格插件** 图标，点击底部的 **自定义插件** 按钮。
在自定义插件面板中点击 **+ 新增插件** 按钮，**填写插件名称及服务地址**，点击 **确定**。」
（新版入口写「左下角侧边栏 → 更多 → 自定义插件」，认「自定义插件」这个词即可。）

- 地址要求：官方原文「**我们没有对域名进行限制，只要是 HTTPS 协议连接都可以正常运行。**」
  ——**只要求 HTTPS**；Replit 给的地址即可。
- 本地调试（可选）：`npm run dev` 起 `http://localhost:5173`，也能填进去预览。
- **不要**在插件里配 AppID / 密钥：官方明说前端插件权限跟随执行人，密钥放前端等于泄露。

## 4. 步骤 C · T1 自检（照着打勾）

打开插件侧边栏后，按顺序核对：

### C1 · 界面与通道（同时验 T2）
- [ ] 标题栏显示 **附件批量导出**
- [ ] 右上角徽标显示 **`本地打包 · tt.request`**（或 `· fetch`）
  - 显示 `tt.request` = 沙箱注入了官方请求通道（首选）
  - 显示 `fetch` = 回退通道，**也能用**，但把它记下来（T2 的结论就是它）
  - 徽标空白/报错 = 插件根本没起来 → 见 §6 排查表

### C2 · 数据源与字段映射
- [ ] 「数据表」能列出目标表（默认当前打开的）
- [ ] 「视图」能列出视图（先选一个有数据的视图，如 `全部记录`）
- [ ] 「附件字段」三行（发票 / 订单截图 / 付款记录）**自动映射**到同名列
  - 若显示 `列名是「XXX」` = 列名不逐字相同但已被选中，属正常
  - 若显示 `未找到该附件字段（请手动指定）` = 下拉手动选一次

### C3 · 读取 + 勾选
- [ ] 点「读取记录」→ 列表出现每行的 部门/购买人/金额/日期/附件情况
- [ ] 点「全选有附件的」（或手动勾 **2 条**记录）
- [ ] 记下「下载所选记录（N 个文件）」里的 N —— **下一步要对得上**

### C4 · 下载与产物
- [ ] 点「下载所选记录」，进度从 `下载中 n/N` 走到完成
- [ ] 浏览器保存出一个 `附件导出_<表名>_<时间戳>.zip`
- [ ] 解压 zip，逐项核对：

  | 检查项 | 期望 |
  |---|---|
  | 目录 | 按「物资所属部门」分文件夹（若选了该分组方式） |
  | 文件名 | 形如 `张某某-2026-06-02-某公司-48.90元-发票01.pdf` |
  | 文件名里没有部门 | 分组已包含的维度会自动从文件名去掉（同一个部门目录内不重复） |
  | 发票/订单/付款 | 扩展名与实际内容一致（PDF 就是 `.pdf`，不是 `.png`） |
  | `manifest.csv` | 双击用 **Excel** 打开**中文不乱码**（UTF-8+BOM）；每文件一行，含 记录ID/审批实例号/槽位/原始文件名/file_token/sha256/字节数/失败原因 |
  | `README.txt` | 有本次导出参数摘要 |
  | 文件数 | = C3 记下的 N（包括失败项也会在 manifest 里出现一行） |
  | 空附件 | 若某行某槽位为空，**不会**凭空产文件，但会在状态里提示 |

### C5 · 抽样对账（与表里核对）
- [ ] 抽 2 个文件，用 sha256 或字节数与表里附件对照（文件大小在附件单元格里可见）
- [ ] 抽 1 行多发票的审批单：确认**勾一行只导那一行的票**（表里是「一张发票一行」）

## 5. T3 · 大批量实测（10–30 条 × 3 附件）

- [ ] 选一个行数较多的视图，全选有附件的（如 30 行 ≈ 90 个文件）
- [ ] 观察：进度条是否持续推进、有没有卡住/白屏、浏览器内存是否飙升
- [ ] 完成后核对 `manifest.csv` 里的**失败行**：应全为空（失败原因列）
- [ ] 重点观察 **10 分钟**这个坎：官方附件链接只活 10 分钟（`docs/30-review/32` F7）。
      代码是「取链接立刻下载」，所以理论上不会撞上；若仍出现 403/过期，
      把失败条数与耗时记下来 → 需要把并发从 3 调到 5 或加重试。
- [ ] 记录总耗时与并发设置（默认并发 3，宿主上限 5）

### T4 · 与官方「附件批量下载」插件对拍
- [ ] 装官方/三方那个「附件批量下载」插件（`docs/30-review/32` §4.1 F10），对**同一批记录**导一次
- [ ] 比对结果：
  - 文件数是否一致（不一致 → 逐个核对是哪个槽位少了）
  - 文件名语义是否能对上（它按原名或首列，我们按规则重命名）
  - 记录到本文 §7 的表格里

## 6. 排查表（按症状）

| 症状 | 最可能原因 | 怎么做 |
|---|---|---|
| 侧边栏一片空白 | Repl 休眠中，或页面报错 | 先直接在浏览器打开那个 URL 看能不能出界面；看 Replit 控制台报错 |
| 徽标显示 `fetch` 而非 `tt.request` | 沙箱没注入 `tt` | 属正常回退（见 T2），记下来即可；若两者都失败 → 下一步 |
| 附件 URL 下载 403 / 被拒 | 当前用户对表/附件无权限；或链接已过 10 分钟 | 换有权限的账号；确认是"取到就下"而不是预取一批 |
| 字段下拉是空的 | 该表没有附件列，或视图选错表 | 确认表里有 `发票/订单截图/付款记录` 三个附件列 |
| 勾了行但导出的文件少 | 该行某槽位本来就空 | 看 `manifest.csv` 的 `状态/失败原因`；空附件行不产文件属预期 |
| 中文文件名解压后乱码 | 用了非 UTF-8 解压工具 | `manifest.csv` 已带 BOM；文件名用系统自带解压 |
| 地址变了插件打不开 | Dev URL 只在编辑时存活（官方原文） | 改用 Static 部署拿固定地址 |
| 只有管理员能装插件 | 表开了高级权限（官方限制） | 让管理员装一次，或临时关高级权限做验证 |

## 8. 与服务端路线的关系（别重复劳动）

- 插件解决的是：**在飞书里勾选 + 立刻拿到 zip**（不依赖 NAS、不依赖 P0 门禁）。
- 插件**做不到**的两件事由服务端路线补（`docs/30-review/32` §5）：
  1. **落 NAS**（票据原图第二副本）；
  2. **导出审计**（谁、何时、照哪份清单、导了哪些票）—— 需求矩阵里的高优先级项。
- 服务端已经落地：
  - `cmd/download-probe`（P0 门禁探测：临时链接 / 权限 / 高级权限 `extra` / 字节数）
  - `cmd/export`（P1 清单导出：清单校验 → 下载 → 命名 → zip → manifest → 审计入库）
  - 命名规则与插件**共用同一份冻结向量**（`bitable-plugin/testdata/naming-cases.json`）。
- 因此 **T4 的对拍结论，可以直接当作 `cmd/export` 的验收参照**。
