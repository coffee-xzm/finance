## 2. 列取舍：一条标准 —— 对人核对有没有用

**删掉 12 列**：

| 列 | 为什么删 |
|---|---|
| 物资名称、是否走大创资金报销、报销类型、备注 | 表单里已经没有 / 从来没有 |
| 归属组 | 表单改回了「物资所属部门」，两列并存只会让人不知道该看哪个 |
| 发票号码来源、分组序号 | 中间产物 |
| 订单号、支付宝交易号 | 中间产物；它们要表达的意思已经在「差异说明」里写成一句话 |
| 配对依据 | 同上 —— 已合并进「差异说明」，不再单列 |
| 发票文件、付款截图 | 改名成 发票 / 付款记录，跟表单一致 |

**保留「发票号码」** —— 用户明确要求保留。它有两重身份：
既是"一张发票一行"的**幂等键**（删了同一张票每次同步都会被当成新行重复写入），
也是人核对时最常拿来对照原图的字段。schema 注释里标了"★ 幂等键之一，勿删"。

**「物资种类」的选项不自动对齐**：实测表单里被加过一个临时项，
按 schema 覆盖会把它删掉，而下一次写入又因为"选项不存在"自动建回来 ——
净效果只是来回折腾。schema 的选项列表只用于**首次建字段**。

## 3. 槽位改名要改五处（这是最容易漏的）

「发票文件→发票」「付款截图→付款记录」不只是改个显示名：

1. `slotRules` 的规范名（决定**表单控件怎么匹配**）
2. `bitable.slots`（决定**附件写哪一列**）
3. `ReviewTable` 的字段名
4. `archive.go` 的 `slotByPrefix` / `carryFields`
5. `store/reindex.go` 的 `slotFromFilename` / `kindFromSlot`

漏改任何一处，表现都是"图不见了"或"字段不存在"。
新增 `TestSlotNamesAreConsistent` 把"三处必须一致"钉成不变量。

## 4. 新表单带出来的两个解析问题

### 4.1 购买人是 contact 控件 —— 值不是人名

实测值：`["u7x2k9qz"]`，8 位短串，**既没有 `ou_` 前缀、也不长**。
原来那套"看长度/前缀猜是不是 ID"的启发式会把它当人名直接写进「购买人」列。

改法：**按控件类型判断**（`w.Type == "contact"` 就是 ID），不猜。
解析出 ID 后用通讯录接口换姓名；换不到就**留空并告警** ——
把一串 ID 写进给人看的列，比空着更糟。

`GetUserName` 也按实际 ID 类型去查（`user_id` / `open_id` / `union_id`）：
类型传错接口直接报 not found，然后人就会以为是"没权限"，白折腾一圈。

### 4.2 发起人部门解析不出来时留空

`detail.DepartmentID` 是 `open_department_id` 或自定义部门 ID。
`buildMeta` 原来拿它给「发起人部门」兜底，于是查不到名字时，
给人看的表里就会出现 `99a8a57fac21fd39` 这种东西。
现在一律留空，ID 另存在 `submission.applicant_dept_id` 里备查。

## 5. 工具补齐

- `cmd/bitable-init -align`：把已存在字段的类型/选项对齐到 schema。
  光靠"新增缺失字段"改不动已存在字段的选项（字段在就跳过）——
  资金来源从一串老师名简化成"个人/老师垫付"就是这种情况。
- `cmd/bitable-init -prune`：删除 schema 里没有的字段。
- `bin/serve -task purge-all`：★危险★ 清空本地库 + 核对/整合表的全部行。

`purge-all` 做了三件容易漏的事：先自动备份；把 `data/extract/files` 挪出
`-reindex` 的扫描路径（不挪的话下次 reindex 会把整批证据装回来）；
表里的行也删（本地清了表没清，人看到的就是一堆对不上号的孤儿行）。

> 实测踩过一个坑：`os.Rename` 不会自动创建**目标路径**的父目录。
> 原代码只 `MkdirAll("backup")`，却要重命名成 `backup/purged-<ts>/files`，
> 目标目录本身不存在 → ENOENT 失败。结果是库清空了、表也清空了，
> 图片却还留在原地 —— 正是这一步要防的事。已修。
